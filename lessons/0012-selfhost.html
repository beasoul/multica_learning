Lesson 12

跑起来：自部署与本地开发两条路

这一课对应 MISSION 里那条硬指标——"两条路都跑通过一次"。好消息是仓库把命令都封好了：你基本不需要手动装 PostgreSQL、也不用手拼 docker compose。

约 45 分钟（含动手） 对应图表：07 自部署拓扑 对应源码：Makefile · SELF_HOSTING*.md · CONTRIBUTING.md · deploy/helm/

一、先分清两条路

只想用起来（自部署）想改代码（本地开发）
目标跑出一个能用的 Multica 服务跑出一个你能改、能断点、能跑测试的实例
用镜像还是源码官方镜像（或从当前 checkout 构建）当前 checkout 源码
命令入口make selfhostmake setup / make start
是否需要 Go / Node 工具链不需要需要
关键事实

所有命令都收敛在仓库根的 Makefile 里。别去猜怎么起环境——make help 就是官方文档。源码里 AGENTS.md 也明确要求用仓库自带的环境脚本，不要自己手工造数据库。

二、路线 A：自部署（最短路径）

# 用官方镜像起一套完整的自部署栈（.env 不存在会自动创建）
make selfhost

# 或者：从当前 checkout 构建后端与前端，再起栈
make selfhost-build

# 停掉
make selfhost-stop

后端起来之后，把 CLI 指过去：

multica setup self-host
# 自定义端口
multica setup self-host --port 9090 --frontend-port 4000
# 自定义域名（生产）
multica setup self-host --server-url https://api.example.com --app-url https://app.example.com

# 或者手工配置
multica config set server_url http://localhost:8080
multica config set app_url http://localhost:3000
multica login
multica daemon start

自部署这件事，仓库给了三份不同深度的文档，按需要挑：

文档适合
SELF_HOSTING.md默认路径：快速起一套能用
SELF_HOSTING_ADVANCED.md进阶：自定义、生产加固
SELF_HOSTING_AI.md与 AI / 模型侧相关的部署
apps/docs/content/docs/environment-variables.zh.mdx环境变量清单

三、路线 B：本地开发环境

这条路的命令设计得很有条理，值得按顺序背下来：

make setup     # 准备当前 checkout：装依赖、确保数据库、跑迁移
make start     # 起后端 + 前端（会先跑迁移）
make status    # 看这个环境在跑什么（含身份证明）
make down      # 停进程，但保留数据库与 profile
make destroy   # 停掉 + 删数据库 + 删 profile + 释放槽位
关键事实

make down 与 make destroy 的区别是本节最重要的一行：down 保留数据，destroy 清空环境并释放槽位。

日常在 down 与 start 之间往返；只有"这个环境我不要了"才用 destroy。

Worktree：多分支并行开发的隔离方式

如果你同时改两个分支，用 git worktree 会各开一份代码目录。仓库对此有专门机制：

make worktree-env    # 为这个 worktree 生成 .env.worktree（唯一数据库名 + 唯一端口）
源码原话

Worktrees share PostgreSQL but have isolated databases/ports. Use the environment scripts and .env.worktree; do not copy the main checkout's .env or manually create a database through an assumed PostgreSQL instance.（AGENTS.md）

翻译：共用同一个 PostgreSQL 容器，但各用各的库名与端口。不要抄主 checkout 的 .env——那样两个环境会指向同一个库，互相污染。

类比

这在 Oracle 里的对应物很直观：所有开发共用一个实例（db-up 起的那个容器），但每人一个 schema，靠 ALTER SESSION SET CURRENT_SCHEMA 切自己的地盘。

区别是这里隔离得更彻底——连端口都分开，所以两个环境能同时跑起来不打架。

只起你要改的那一部分

make api-dev        # 只跑 Go 后端
make web-dev        # 只跑 Next.js 开发服务器
make desktop-dev    # 只跑 Electron 桌面端
make env-exec ARGS="-- pnpm dev:desktop"   # 用本环境的变量跑任意命令

数据库的日常操作

make db-up      # 起共享 PostgreSQL 容器（主 checkout 与各 worktree 公用）
make db-down    # 停容器，但保留数据卷
make db-reset   # 删掉并重建当前环境的库，然后重跑全部迁移
make db-drop    # 永久删除当前环境的本地库（会先要你确认）

db-reset 是你调试迁移时最常用的：它把第 10 课那 589 组迁移从头跑一遍，正好用来验证自己的迁移能不能一次跑通。

四、验证代码改对了没有

make check        # 一个命令跑完：typecheck + TS 测试 + Go 测试 + Playwright E2E

也可以按范围拆开跑（迭代时更省时间）：

范围命令
前端（不含 mobile）pnpm typecheck · pnpm lint · pnpm test
Go 后端make test
端到端pnpm exec playwright test
mobile见 apps/mobile/AGENTS.md（根命令不覆盖 mobile）
小心

两条容易踩的边界：

  • 根目录的前端命令与 make check 不验证 mobile。改了移动端要单独跑它的验证。
  • 只改文档时可以用链接/引用检查和 git diff --check；但要在说明里明说没跑代码测试，不要让它看起来像全绿。

五、生产部署与健康检查

生产路径是 Helm chart，位于 deploy/helm/multica/。本课不深入 K8s，但有两个数字必须记住：

  • 启动探针给了 10 分钟——因为迁移在后端启动时执行（第 10 课），大表上的索引构建可能很久。
  • 迁移被中断留下的无效索引，runner 在下次启动时会自行清理。

健康检查三个端点，语义不同：

端点语义
/health存活：进程活着（不查数据库依赖）
/readyz 与 /healthz就绪：可以接流量了（依赖检查通过）
/health/realtime实时子系统指标：连接数、慢客户端驱逐、各事件类型发送 QPS。可用 REALTIME_METRICS_TOKEN 加访问限制；未设置时只服务回环调用

六、动手清单（照着做一遍）

  1. make selfhost，等它起来。
  2. 浏览器打开前端地址，注册/登录，建一个工作区。
  3. 在另一台终端 multica setup self-host 接上，再 multica daemon status，确认检测到了本机 CLI。
  4. 建一个 Issue 指派给某个 Agent，观察它是否从 queued 走到 running。
  5. make selfhost-stop。
  6. 再走一遍开发路线：make setup → make start → make status → make down。

走完这六步，MISSION 里"两条路都跑通过一次"那条就算达成了。

2. 你在一个 worktree 里开发，为什么不直接复制主 checkout 的 .env？

3. 你想让编排系统"数据库连不上时先把流量摘掉、但别重启容器"，应该配哪个端点？

不看上文，写出从零到"能改代码并验证"的命令序列。

# 想直接用（不自建源码）
make selfhost
multica setup self-host
multica daemon start

# 想改代码
make setup            # 装依赖 + 确保数据库 + 跑迁移
make start            # 起后端与前端
make status           # 确认在跑什么
make check            # typecheck + TS 测试 + Go 测试 + E2E
make down             # 停进程，保留数据

# 需要时
make worktree-env     # 多分支并行：生成隔离的 .env.worktree
make db-reset         # 重建库并重跑全部迁移（验证迁移用）
make destroy          # 彻底清空这个环境

判断口诀：只想用 → selfhost；要改代码 → setup/start/check/down；多分支 → worktree-env。
