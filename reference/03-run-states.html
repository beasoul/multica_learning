Reference 03

Run 状态与失败原因

任务卡住或失败时对照这张表。原则：先看停在哪个状态，再走对应分支——不要从故障清单第一条开始逐条试。

约 6 分钟对应课程：0005、0006、0007、0014

状态全集

状态含义谁推进它是否终态
deferred已创建但未到 fire_at，完全不动调度器到点 → queued否
queued在队列里等 Runtime 认领daemon 认领 → dispatched否
dispatched已被认领，凭据已签发，CLI 未起daemon 启动 CLI → running；目录被占 → waiting_local_directory否
waiting_local_directory目标本地目录被另一条在途运行占用目录释放 → running否
runningAgent CLI 进程在跑进程结束 → completed / failed否
completed正常结束，交回评审—是
failed出错结束，带错误信息—是
cancelled被人或系统取消—是（可从任意状态进入）

创建时的分叉规则：CASE WHEN fire_at IS NOT NULL THEN 'deferred' ELSE 'queued' END（pkg/db/queries/agent.sql）。

状态 → 事件 → 下一步

事件转移
task:queued∅ → queued（入队 / 重试创建）
task:dispatchqueued → dispatched（daemon 认领）
task:runningdispatched → running（daemon 已启动）
task:waiting_local_directorydispatched → waiting_local_directory
task:progress过程上报，不改状态
task:completed / task:failedrunning → 终态
task:cancelled任意状态 → cancelled

停在非终态：分诊表

停在含义依次检查
queued 没有运行时来领 1. 绑定的 Runtime 是否在线
2. Runtime 是否检测到该 Agent 配置的工具
3. Agent 是否还有并发额度（默认 6）
4. daemon 是否还有全局容量（默认 20）
dispatched 认领了但没走到"开始" daemon 是否中途崩溃 / 网络断开；看 daemon 日志与 GetTaskStatus 记录
waiting_local_directory 同一本地目录被占用 等前一条结束；或把项目资源切到 worktree 模式（并行，无队列）；
互斥是 daemon 内存态，要释放就 multica daemon restart——没有锁文件可删
running 但无产出 工具起了但没进展 工具是否已登录 / key 与额度 / 模型与思考级别是否被支持 / 目录是否存在可写 / 自定义参数是否有效；
最快验证：在执行那台机器上手工运行同一工具
deferred 一直不动 未到点 看它的 fire_at；这不是故障
重要澄清

"排队久"本身不是故障。运行时离线时运行会继续排队；只有该运行时心跳缺席超过重连宽限期、并且这条运行自己也已等满这么久才会失败。所以长队列不会因等太久被判失败，指派给已离线机器也仍留有一个完整宽限期把它唤醒。

失败：去哪儿找原因

线索在哪
Run 的失败原因字段Run 详情 / multica issue runs <issue-id>
运行的完整消息流（工具调用、思考、错误）multica issue run-messages <task-id>（可用 --since 增量拉）
daemon 侧现场multica daemon logs --lines 100
daemon 启动过程multica daemon start --foreground
失败归类逻辑server/pkg/taskfailure/
后端日志（自部署）docker compose -f docker-compose.selfhost.yml logs -f backend
