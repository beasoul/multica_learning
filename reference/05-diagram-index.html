怎么改这些图

每张图都由 diagrams/_src/ 下同名 JSON 规格渲染而来。改图改规格，不要直接改 HTML。

C:\coding\learning\diagrams\
├─ 01-system-architecture.html      ← 已交付的可离线打开版本
├─ 02-repo-layers.html
├─ ...
└─ _src/
   ├─ 01-system-architecture.json   ← 源头在这里
   ├─ 02-repo-layers.json
   └─ ...

重新渲染的流程是两步：先 校验（9 项构图检查），再 交付（冻结 + 渲染成独立 HTML）。八张图当前全部通过校验：9/9 项、0 错误、0 警告。

类比

这套"规格 → 校验 → 交付"很像你熟悉的数据库变更流程：JSON 是 DDL 源文件，校验是编译期检查，HTML 是已部署的产物。直接改产物等于在数据库里手改数据而不改脚本——下次重新渲染就白改了。

八张图各自的结构要点

图看的时候重点盯住
01 系统架构总览四种客户端 → 一台服务端 → 你自己机器上的 daemon 与工具进程。服务端从不下场执行。
02 仓库分层views 指向 core + ui；ui 没有任何反向箭头；Mobile 只碰 core 的类型。
03 Run 生命周期主干 queued → dispatched → running → 终态；两条岔路分别指向排期与等目录；cancelled 从所有状态汇入。
04 端到端时序第 3 步（claim + 签发令牌）到第 6 步（spawn 注入令牌）之间那条凭据暗线。
05 daemon 唤醒与领取推送与轮询两条路径在哪一步汇合（claim）。
06 实时数据流事件从"变更发生"到"UI 重渲染"的完整路径，以及两条通道各自的入口。
07 自部署拓扑daemon 永远在你那侧，不在服务器上。
08 权限校验链凭据在哪一步被换成范围更小的那一枚。
